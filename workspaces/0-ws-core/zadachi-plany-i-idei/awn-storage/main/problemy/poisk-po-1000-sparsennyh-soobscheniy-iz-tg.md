Вот сводка проблем и решений, которые мы обсудили — можно скопировать целиком и отправить агенту.

Контекст задачи

Скачан архив переписки из Telegram — около тысячи сообщений. Стоит задача передать их LLM-агенту (Claude или аналогу) для разбора и анализа. Ниже — ключевые проблемы, с которыми это сопряжено, и возможные решения.

**Проблема 1: Постановка задачи**

Модель заранее не знает, что именно важно в переписке — какие темы, люди, периоды, договорённости или факты нужно вытащить. Без чёткого технического задания («что искать», «по каким критериям», «в каком виде выдать результат») модель будет действовать наугад, и качество разбора сильно упадёт.

**Проблема 2: Формат хранения сообщений**

Хранить каждое сообщение в отдельном markdown-файле — плохая идея при объёме в тысячу штук: неудобно искать, листать, засоряется файловая система. Лучше группировать сообщения — по дню, по теме или по автору — в один файл, со структурой на каждое сообщение: дата/время, автор, текст, ссылка на сообщение-родитель (если это ответ). Формат — JSON или таблица (CSV), это легче фильтровать и обрабатывать порциями.

**Проблема 3: Непредсказуемый размер файла при прямом чтении**

Модель заранее не знает точный размер файла или количество сообщений в нём, пока не откроет его. Если открыть большой файл целиком «одним махом», он может занять весь доступный контекст модели за один заход.

**Проблема 4: Накопление объёма в контексте даже при чтении по частям**

Даже если резать файл на части и обрабатывать последовательно (сохраняя после каждой части краткую выжимку), сам процесс чтения через диалоговый контекст всё равно расходует место — просто медленнее. При действительно большом объёме данных контекст всё равно закончится, и потребуется либо начинать новый разговор, либо укрупнять блоки, чтобы уменьшить число итераций.

Решение: обработка данных без прямой загрузки в контекст

Вместо того чтобы модель читала весь текст «глазами», данные загружаются в базу — обычную базу данных или векторное (семантическое) хранилище. Дальше модель делает точечные запросы к этой базе через код:

поиск по ключевым словам, дате, автору;подсчёт статистики;смысловой (векторный/семантический) поиск — когда ищутся не точные фразы, а совпадения по смыслу с заданным вопросом.

В контекст в этом случае попадают только результаты запроса (например, десять релевантных сообщений или посчитанные цифры), а не весь массив исходных данных. Это и есть правильный подход для больших объёмов текста вроде архива переписки.
