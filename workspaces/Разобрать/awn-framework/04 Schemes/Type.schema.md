## AWN-ID

**Тип:** строка. Машинный уникальный идентификатор в формате **UUID v4**
в нижнем регистре, всегда в двойных кавычках.

Создаётся один раз при создании файла и **никогда не меняется** —
даже при переименовании или перемещении.

Генерация (macOS / Linux, без зависимостей):

```bash
uuidgen | tr 'A-Z' 'a-z'
```

## AWN-SLUG

Уникальное человекочитаемое имя типа. Верхний регистр, разделитель `/`.
В отличие от `AWN-ID`, slug **можно менять** при переименовании типа.
Связи между файлами идут по `AWN-ID`, а не по slug.

Два официальных неймспейса:

- `COMPONENT/*` — структурные ноды: `COMPONENT/WORKSPACE`, `COMPONENT/SPACE`, `COMPONENT/PART`.
- `MEMORY/*` — виды памяти: `MEMORY/LOG`, `MEMORY/SIDECAR`, `MEMORY/CONTENT/INNER`.

Slug отражает путь в дереве типов — вложенность сегментов соответствует
вложенности папок в `02 Components/`.

## AWN-TYPE

Форма ноды:

- `Folder` — нода-папка (маркер-файл внутри папки)
- `File` — нода-файл (один `.md`)

## AWN-ALLOW-CHILDREN

Разрешены ли дочерние ноды внутри элемента.

- `true` — контейнер
- `false` — конечный «тупик»

## AWN-LAYER

Архитектурный слой контекста, к которому относится тип. Целое число от `0` до `5`.

| Слой | Название | Что включает                                                                 |
| ---- | -------- | ---------------------------------------------------------------------------- |
| `0`  | Vault    | Корень workspace                                                             |
| `1`  | Folder   | Папки-ноды: Space, Cluster, Book, Collection. Общий контекст и правила       |
| `2`  | File     | Файлы-ноды: Part. Самостоятельные объекты                                    |
| `3`  | Memory   | Виды памяти: Content, Log, Sidecar, Volume. Следы, опыт, факты, воспоминания |
| `4`  | Vision   | Представления данных (Views): дашборды, канбаны, mindmap                     |
| `5`  | External | Все остальные файлы (не-ноды): медиа, скрипты, конфиги                       |
## AWN-NAME

Человекочитаемое короткое имя типа. Используется в заголовках и UI.
Примеры: `Workspace`, `Space`, `Part`, `Volume`.

## AWN-DESC

Краткое описание типа в 1–2 строки. Что это и зачем нужно.

## AWN-REGISTRY

Регистрируется ли тип в `awn.registry.md` как нода с маршрутом.

- `true` — тип попадает в реестр (типичный пример — `COMPONENT/SPACE`, `COMPONENT/PART`).
- `false` — тип в реестр не заносится (память, спутники, external).
