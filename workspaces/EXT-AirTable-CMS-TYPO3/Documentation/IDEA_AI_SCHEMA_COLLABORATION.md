# Идея: совместная работа с ИИ только над структурой данных

**Статус:** концепция для RecordPilot / универсальной админки  
**Связанные артефакты:** `services.schema.idea.json`, макет «Схема-чат» в `EXAMPLE.html` · **карта всего документа макетов:** якорь `#recordpilot-doc-hub` в конце `EXAMPLE.html`

## Зачем

- Обсуждать с ИИ **поля, связи, именование, валидацию, новые типы** безопаснее, чем отдавать произвольный доступ к прод-БД.
- ИИ помогает **формулировать метаданные** и черновики схем; **исполнение** (миграции, код, деплой) остаётся за человеком и пайплайном.

## Что можно обсуждать (в зоне ответственности ИИ)

| Тема | Пример вопроса | Что на выходе |
|------|----------------|---------------|
| Новый тип поля | «Нужно поле Виджет: выбор пресета + JSON настроек» | Описание в `adminSchema.fieldConfig`, варианты хранения (колонка JSON vs отдельная таблица) |
| Связи | «Как связать заявку с услугой M2O?» | Имя FK, индексы, каскады, подписи в UI |
| Валидация | «Slug уникален в пределах категории» | Правила + кандидат уникального индекса |
| Именование | «Как назвать поле для срока действия справки?» | RU/EN метки, machine name |
| Расширяемость | «Как не ломать ядро при кастомном поле?» | Контракт: `FieldType` + регистр типов |
| Контроль качества | «Что обязательно перед публикацией?» | Чек-лист полей, блокеры публикации (см. макет 33 в EXAMPLE) |
| **Визуальный виджет (диаграмма)** | «Пресет bar chart, потом данные с отчётного API» | JSON: `uiType: chart`, `engine` (Chart.js / ECharts), `dataBinding`, **mock-данные только для превью в админке**; на сайте рендер по сохранённому конфигу |
| **Обсуждение записей (CRUD)** | «Выборка, вставка, обновление, удаление — без SQL в чате» | Контракты `list` / `create` / `update` / `delete` (REST или RPC), soft delete, права; ИИ выдаёт черновик схемы API, не выполняет команды |

### Визуальные виджеты и диаграммы

- В режиме **«только структура»** ИИ помогает описать **конфиг графика** (тип, оси, легенда, источник данных *в абстракции*: `report_id`, `endpoint`, а не выгрузка строк).
- **Превью в форме** можно рисовать из **фиктивных чисел** в метаданных или из тестового набора — без доступа к прод-таблицам.
- Реализация: поле-хранилище **JSON** + зарегистрированный компонент «Chart preview»; фронт сайта читает тот же JSON и подключает выбранную библиотеку.

## Чего не делать через тот же чат без жёстких ограничений

- Произвольные **SELECT/UPDATE** по прод-данным без read-only и ревью.
- Автоматическое применение миграций без CI и бэкапа.

## Как расширять проект под кастом (например «Виджет»)

1. **Контракт типа поля** в коде (метаданные, валидация, отображение в форме/списке, API).
2. **Реестр** `type_code → класс или компонент UI`.
3. Хранилище: часто **JSON** + схема (JSON Schema) или фиксированные подполя.

ИИ в этом процессе генерирует **черновик описания** и **псевдокод**, а разработчик встраивает в реестр и тесты.

## Визуализация

См. в `EXAMPLE.html` секцию **«ИИ-помощник по структуре»** (`#idea-ai-schema-chat`): темы слева, диалог справа, в том числе пример **столбиковой диаграммы** с блоком **превью на mock-данных** (без запроса к прод-БД).
