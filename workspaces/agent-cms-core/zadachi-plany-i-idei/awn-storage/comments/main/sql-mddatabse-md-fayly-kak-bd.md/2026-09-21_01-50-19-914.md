**Кратко: 1000 записей агенту не отдают — сначала сужают, потом читают точечно.**

### Как работать с большим `awn-storage/main`

1. **Не «все записи»**, а **поиск / фильтр**:
   - `search_workspace_hybrid` / `search_workspace_content` — по смыслу/тексту, `limit` 20–50
   - `query_workspace_storage` — по полям (`awn-focus`, `awn-status`, tags…), `limit` до 500, `fields` — только нужные колонки
   - `pathPrefix` — ограничить одной темой или подпапкой `…/awn-storage/main/…`

2. **Обзор без тел** (легче, но всё равно может быть тяжело при 1000):
   - `get_content_index(path, slot=main)` — только path/type/title/description
   - `get_content_map` — только когда нужны properties; на 1000 записей не тянуть

3. **Работа порциями**:
   - нашли 30 нужных → `read_content_body` / `write_content_property` точечно
   - пакетно — `batch_invoke`, но read до 20, write до 10 за раз

4. **Смысловые срезы**:
   - `awn-focus: true` — «активный» набор (как ⊙ в UI)
   - подпапки в `main` — естественное дробление
   - вопрос «что было по X?» → `ask_workspace` / `search_and_get_context` (~8 цитат, не весь архив)

**Итого:** модель **«индекс → фильтр → top-N → точечное чтение/правка»**, а не «выгрузить весь main агенту». Для массовых операций по сотням записей сейчас нет одного bulk-tool — только фильтр + цикл/batch.
