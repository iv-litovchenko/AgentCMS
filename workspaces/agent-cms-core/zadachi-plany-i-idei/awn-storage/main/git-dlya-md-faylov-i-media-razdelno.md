10. ГИТ

* git add ":/*.md" (yml, json, csv, txt)
* git add ":" ":(exclude)*.md"

Добавить все .md файлы в кастомную папку базы данных .gitfiles
git --git-dir=.gitfiles add ":/*.md"

Сделать коммит туда же
git --git-dir=.gitfiles commit -m "My commit"



Смотри, коротко, по пунктам, всё, что обсудили.

Первое — Git LFS. Ты помечаешь расширения бинарных файлов в файле .gitattributes, и git при коммите автоматически подменяет тело файла на текстовый указатель, а сам файл кладёт в LFS-хранилище. Команды те же самые — add, commit, push — просто в фоне подключаются LFS-хуки.

Второе — версионирование. Каждая новая версия бинарного файла хранится как полностью отдельный объект, дельты как с текстом git не считает, поэтому история тяжёлых файлов быстро раздувает хранилище, и для этого есть команда очистки, git lfs prune.

Третье — сеть и адреса. В конфиге у тебя два адреса, обычный remote.origin.url для коммитов и отдельный lfs.url для тел файлов, они могут быть на одном сервере или на разных.

Четвёртое — надёжность передачи. При пуше сначала уходят тела файлов, и только потом коммиты, поэтому ты никогда не получишь битую ссылку без файла — если что-то не долетело, можно просто повторить пуш.

И пятое — альтернатива без LFS вообще. Выносишь все бинарники в отдельное S3-совместимое хранилище, а в git оставляешь только код и текст, в базе — ссылки на файлы. Для Agent CMS, где важнее скорость отдачи, чем история версий, этот вариант обычно практичнее.
