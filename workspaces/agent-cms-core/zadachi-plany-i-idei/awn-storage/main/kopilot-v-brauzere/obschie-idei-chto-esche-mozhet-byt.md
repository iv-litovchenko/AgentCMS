# Общие идеи что еще может быть

Заметка про **companion toolbar** (`browser-extension/`): что ещё может быть полезным сверх текущего набора.

## Что уже есть (база)

Сейчас капсула — это в основном **«снять контекст со страницы и положить в compose агента»**:

- **Выбор** — page picker, клик по блоку
- **Скрин** — видимая область вкладки → `.agent-shell/screen/` + вставка в compose
- **Страница ▾** — заголовок и ссылка / текст / Markdown
- **Текст ▾** — выделение + промпты (прочитай, объясни, конспект, перевод, задача)
- Перетаскивание капсулы (влево / вправо / вверх)
- Side Panel по второму клику на иконку

Архитектура: `content-script.js` → `COMPANION_COMPOSE_INSERT` → Side Panel. Page picker умеет спец-извлечение для CMS (`page-picker-extract.js`), мета страницы — `page-snapshot.js`.

---

## Уровень 1 — ещё «снять контекст» (лучше всего ложится на текущую модель)

### Ссылки

- Все ссылки из `article` / `main` / только из видимой области
- «Ссылка под курсором» (если делать hover-щуп)
- На localhost CMS — отдельный пункт **Workspace-путь** (логика уже есть в `page-picker-extract.js`)

### Структурированные фрагменты

- Клик по `<table>` → Markdown-таблица
- Клик по `<pre><code>` → блок кода с языком
- `<blockquote>` → цитата с источником

### Мета страницы

Уже почти есть в `page-snapshot.js`:

- OG-карточка: title, description, canonical, og:image
- «Кратко о сайте» — одной строкой для агента

### Выделение+

- Не только plain text, но и **HTML / Markdown выделения**
- «Выделение + URL + заголовок» одним пакетом

### Скрин области, а не всей вкладки

- Скрин **выбранного блока** (element screenshot)
- Полезно для статей, форм, ошибок, UI-багов

### История вкладки

- Последние 3–5 вставок с этой вкладки
- Мелочь, но удобно при длинной работе с одной страницей

## Уровень 2 — взаимодействие со страницей (без «агент сам всё кликает»)

### Заполнить поле

- Выбрал `input` / `textarea` → «Вставить из compose / из буфера / из ответа агента»
- Обратный поток: не только page → agent, но и agent → page
- Формы, поиск, комментарии

### Копировать в буфер

- «Скопировать как Markdown / plain / link»
- Без открытия Side Panel — быстрый экспорт

### Прокрутка / якорь

- «Скопировать ссылку на этот блок» (`#fragment` или generated id)
- «Прокрутить к заголовку H2…» — мини-оглавление страницы в меню **Страница**

### Подсветка для себя

- Временно подсветить блок жёлтым / обвести рамкой
- Только overlay, не меняет DOM сайта навсегда
- Удобно перед скрином или обсуждением с агентом

### Compare

- Выбрать два блока → «Сравни эти два фрагмента»
- Прайсы, две версии текста на одной странице

## Уровень 3 — «выполнение действий» (осторожно, но мощно)

Разделить два режима:

1. **Действие по явному клику пользователя** — безопаснее
2. **Действие от агента через расширение** — сложнее, нужны guardrails

### По клику пользователя

- **Открыть в CMS** — на localhost: workspace-path → открыть в CMS
- **Сохранить в inbox CMS** — страница или фрагмент с веба
- **Создать задачу / заметку** — не только промпт «Задача», а structured POST в inbox/thread
- **Отправить агенту сразу** — toggle «вставить» vs «вставить и отправить» (сейчас всё только в compose)
- **Follow link** — для ссылки под picker: открыть + параллельно положить контекст агенту

### От агента (MCP / remote hands)

В Shell уже задуманы инструменты вроде `shell_screenshot`, clipboard, window. Companion может стать **руками агента на веб-странице**:

- `companion_click(selector)`
- `companion_fill(selector, text)`
- `companion_scroll(to)`
- `companion_extract(selector)`
- `companion_screenshot(region)`

Нужны: permissions, подтверждения, audit log («агент хочет нажать Submit»).

## Особенно хорошо стыкуется с текущим UX капсулы

### 1. Щуп в свёрнутом виде

- Навёл иконку на страницу → подсветка блока + тип («абзац», «ссылка», «картинка»)
- Отпустил → вставка в compose
- Заменяет отдельную кнопку **Выбор** для большинства кейсов
- Работает **только когда капсула свёрнута**; в развёрнутом виде — просто drag без подсветки
- Debounce ~300 ms над одним блоком, чтобы не мигало

### 2. Меню «Страница» → «Контекст ▾»

- Заголовок и ссылка
- Текст страницы / Markdown
- Оглавление (H2–H4)
- Ссылки из статьи
- OG / meta
- Workspace path (на CMS)

### 3. Меню «Текст» → «С агентом ▾»

- Вставить выделение
- Промпты (прочитай, объясни, …)
- Сравнить с…
- Перевести и вставить обратно на страницу (если поле editable)

### 4. Скрин — три режима

- Видимая область *(есть)*
- Выбранный блок
- Элемент под иконкой при drag (hover-щуп)

## Что не пихать в капсулу

- Автоклики по сайту без явного режима
- «Агент, сделай всё на странице»
- 15 иконок в ряд — капсула про компактность
- Дублирование всего Shell toolbar (камера, TTS, send) — для этого Side Panel

## Практичный roadmap

### Ближайшие 3 пункта (макс. польза / мин. сложность)

1. **Блок ▾** — результат element picker: текст / md / скрин блока / ссылка-якорь
2. **Ссылки** — список ссылок из `article` / `main`
3. **Meta** — OG + canonical одним пунктом

### Следующий слой

- Hover-щуп в свёрнутом состоянии
- «Вставить в поле на странице»
- «Отправить сразу», не только в compose

---

## Принцип

Toolbar сильнее всего там, где он **быстро превращает страницу в структурированный контекст для агента**.

«Выполнение действий» имеет смысл, но лучше начинать с **явных, обратимых, пользовательских** действий (скопировать, подсветить, заполнить поле, сохранить в CMS), а не с автоматизации кликов.
