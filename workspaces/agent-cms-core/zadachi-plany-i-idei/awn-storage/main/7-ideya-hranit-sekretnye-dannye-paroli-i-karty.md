пароли и секретные данные

Дополнительные идеи

**Предлагаю так:**

1. **Секреты — только в `.env`** (или `.env.local`, в `.gitignore`).
2. **В CMS** — не значение, а ссылка: имя переменной (`ELEVENLABS_API_KEY`) или флаг «из env».
3. **Bridge/runtime** — при чтении настроек: `workspace.yml` → если пусто, брать из `process.env`.
4. **Миграция** — один раз вытащить ключи из `workspace.yml` в `.env`, из yaml удалить/очистить.
5. **В UI** — поле readonly: «задаётся в .env», без показа ключа.

**Сейчас не срочно**, если workspace не в git и только локально. **Срочно** — если репозиторий общий или ключ уже светился в файле.

Итог: полноценный «сейф паролей» не сделан; планировали как отдельную фичу. Для TTS-ключей сейчас логичный первый шаг — .env, как в пресете, а не vault.
