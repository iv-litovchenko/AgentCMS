Да — в задумке и уже частично на практике это саморасширяемая система. Но не «магия без кода», а одна модель на всех уровнях, которая позволяет расти внутри себя.

## Где пока граница (не 100% self-hosting)

| Слой | Сейчас |
| ---- | ------ |
| Данные, схемы, доки | ✅ в workspace, расширяются топиками |
| Loaders / API / UI-виджеты | ⚙️ код в `server.js`, `*-loader.js` |
| Новый block в редакторе | schema есть, рендер — в JS |
| MCP tool | schema (план), реализация — в `mcp-server/` |

То есть: онтология и контент — саморасширяемы, поведение runtime — пока задаётся кодом, а core workspace только документирует и этalon-ит правила.

***

## Короткая формула

> CMS = язык описания мира агента.
> `agent-cms-core` = грамматика этого языка.
> Агенты = тексты на языке.
> JS = интерпретатор (пока снаружи).

Когда loader начнёт читать `**/configuration/schema.yml` из core — связь станет ещё tighter: спека и runtime сойдутся в одном источнике.

***

## Ответ одной фразой

Да — саморасширяемая в слое модели и данных (области, топики, типы, справочники, конфиги тем).
Частично — в слое поведения (новые UI-режимы, tools, хуки всё ещё требуют кода, но их уже можно *описывать* в core как топики).
Если хочешь, могу оформить это как короткий топик `types-of-components/nodes/self-extending.md` или абзац в `platform-map.md`.
