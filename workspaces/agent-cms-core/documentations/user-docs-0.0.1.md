# Agent CMS — документация (v0.0.1)

File-based CMS для агентов без базы данных.

> [!NOTE]
> **Версия 0.0.1 — актуальная.** В модалке **DOC** (и в **API** / **MCP**) в select выберите **«Актуальная (0.0.1)»**. Пункт **«Предыдущая (0.0.0)»** — укороченный снимок старой справки.

---

## Быстрый старт

1. Выберите **агента** в левой панели (workspace на диске).
2. Откройте **ноду** в дереве.
3. Редактируйте описание, память, файлы и свойства — сохраните изменения.

Запуск: `npm start` → http://localhost:3000

---

## Что такое нода

**Нода** — единица контента в workspace агента. Это обычная папка на диске, у которой есть манифест **`_.node.md`** (служебный маркер: «эта папка = нода»).

Нода объединяет в одном месте:

- **описание** — инструкции, правила, документация, контекст для агента;
- **свойства** — метаданные в `_.props.yaml` (title, tags, color, …);
- **память** — однофайловую, многофайловую, табличную, inbox, TODO;
- **файлы** — медиа, документы, скрипты, конфиги;
- **дочерние ноды** — вложенные папки с собственным `_.node.md`;
- **parts** — подразделы внутри `_Parts/` (отдельные `.node.md` или вложенные папки).

Нода появляется в дереве слева, когда в папке есть `_.node.md`. Имя в меню берётся из **имени папки**, а не из заголовка в markdown.

Корень workspace — тоже нода: `_.node.md` в корне агента.

> [!NOTE]
> Папки `_Storage` и `_Parts` в дереве **не показываются** как отдельные пункты — это служебная структура внутри ноды.

## Интерфейс

### Шапка

| Кнопка | Назначение |
|--------|------------|
| **API** | HTTP API — select **Актуальная (0.0.1)** или Предыдущая (0.0.0) |
| **MCP** | MCP tools — select **Актуальная (0.0.1)** |
| **DOC** | Руководство — select **Актуальная (0.0.1)** (эта страница) |
| **MD** | Справочник Markdown preview |
| **Поиск** | По содержимому файлов в workspace |

Под заголовком — **хлебные крошки** текущего пути и кнопка **Сохранить**.

### Левая панель (sidebar)

**Выбор агента** — переключение между workspace. Каждый агент — отдельная папка на диске (`acms.agents.json`).

**Режимы дерева** (🌳 📋 🗂️ ⭐):

| Режим | Описание |
|-------|----------|
| Древовидная | Классическое дерево папок и нод |
| Плоская | Список всех нод без вложенности |
| Карточки | Ноды карточками с превью; фильтр «Только с превью» |
| Закладки | Избранные ноды (⭐ на элементе меню) |

**Поиск по дереву** — фильтрация пунктов меню по имени.

**Дерево нод** — основная навигация по workspace.

У **папок** в дереве (ноды и группирующие секции) **перед названием** могут отображаться маркеры, если **в этой папке на диске** есть:

| Маркер | Условие | Значение |
|--------|---------|----------|
| Оранжевая иконка Git | В каталоге папки есть `.git` | Git-репозиторий с корнем в этой папке |
| Фиолетовая иконка Obsidian | В каталоге папки есть `.obsidian/` | Obsidian vault с корнем в этой папке |

Маркеры **не наследуются** от родительских папок — только локальное наличие `.git` / `.obsidian`.

Маркеры видны в режимах **Древовидная**, **Плоская** и **Закладки**. Проверка выполняется при загрузке меню (`GET /api/menu`): у каждой папки в `sections[]` и у корня workspace — поля `hasGit`, `hasObsidian` (и `hasGitSelf`, `hasObsidianSelf`).

> [!NOTE]
> Скрытые служебные каталоги (`.git`, `.obsidian`) **не** показываются отдельными пунктами дерева — только маркером на родительской папке.

**Служебные файлы** (внизу sidebar) — файлы уровня агента, не привязанные к одной ноде:

`AGENTS.md`, `README.md`, `TODO.md`, `docker-compose.yml`, `.env`, `.gitignore`, `acms.dependencies.json`, `acms.deps.json`, `acms.map.json` (карта элементов — на будущее)

Точка статуса:

- **зелёная** — файл есть и не пустой
- **жёлтая** — пустой или отсутствует

**⚙** внизу sidebar — реестр агентов (ID, workspace, среда).

### Рабочая область (workspace)

При открытой ноде:

- **заголовок** — редактируемое имя ноды;
- **панель YAML** — свойства `_.props.yaml` (можно свернуть);
- **редактор** — режимы Просмотр / Источник (WYSIWYG временно отключён);
- **списки файлов** — для режимов памяти, медиа, скриптов и т.д.

**⚛️ Пространство ноды** — обзор связей ноды (граф), без редактора.

### Icon rail (слева от контента)

Вертикальная панель групп режимов. Порядок сверху вниз:

| Иконка | Группа |
|--------|--------|
| ⚛️ | Пространство ноды (граф) |
| 🧭 | Навигация |
| 🧠 | Память |
| 📎 | Файлы |
| ⚙️ | Настройки |
| ⚡ | Автоматизация |
| ✨ | Дополнительно |

Клик по группе открывает **flyout** со списком режимов справа от rail.

## Разделы ноды (режимы содержимого)

Каждый режим — отдельный «слой» данных ноды. Переключение не меняет выбранную ноду, только то, **что** вы редактируете.

### ⚙️ Настройки

| Режим | Файл / папка | Назначение |
|-------|----------------|------------|
| **Описание, инструкции, правила** | `_.node.md` | Главный текст ноды: контекст, правила, инструкции для агента |
| **Конфигурации** | `_Storage/Configuration.md` | Настройки и конфигурация ноды |
| **Скрипты** | `_Storage/_Scripts/` | Скрипты автоматизации (список `.md`-манифестов) |
| **.env** | `_Storage/.env` | Переменные окружения ноды |
| **TODO** | `_.node.todo.md` | TODO-лист ноды |
| **Превью** | `_Storage/_Preview/` | Картинка превью для карточки в меню |

### 🧠 Память

На **обзоре ноды** (overview) всегда показаны три **драйвера памяти** — способы хранить то, что агент использует в работе. Какой из них нужен, не задаётся свойствами: файлы и папки создаются по факту, когда вы открываете нужный режим.

| Драйвер (ID) | Режим в UI | Где хранится | Простыми словами |
|--------------|------------|--------------|------------------|
| `internal` | **Однофайловая** | `_.node.main.md` | Произвольное содержимое в одном файле — загружается в контекст агента за один раз |
| `external` | **Многофайловая** | `_Storage/_Content/` | Книги, коллекции и данные с произвольной структурой в папках |
| `tabular` | **Табличная** | `_.node.main.csv` | Таблица с данными (как Excel) — для данных, которые загружаются в контекст за один раз (пример: счётчик изучения английских слов) |

**Как выбрать:**

- один файл, весь контекст сразу → **однофайловая**;
- много файлов, материал растёт → **многофайловая**;
- таблица с данными (как Excel), загрузка в контекст за один раз → **табличная**.

Дополнительные режимы группы «Память»:

| Режим | Файл / папка | Назначение |
|-------|----------------|------------|
| **Входящие** | `_Storage/_Inbox/` | Черновики и необработанные заметки |
| *Многофайловая (БД)* | — | В разработке |
| *Источники* | `_Storage/_Referenses/` | В разработке |
| *Рассуждения (volume)* | — | В разработке |

#### Однофайловая (`internal`)

Один markdown-файл `_.node.main.md` — пара к `_.node.md`. Для произвольного содержимого, которому не нужна многофайловая память: правила, инструкции, большой текст, справочник. Данные загружаются в контекст агента **за один раз** — без сложных фильтраций и поиска по разным файлам.

#### Многофайловая (`external`)

Папка `_Content/` внутри `_Storage/`. Отдельные `.md`-файлы и вложенные папки — произвольная структура, как файловая библиотека. Подходит для книг, коллекций и материалов, которые пополняются со временем.

#### Табличная (`tabular`)

Файл `_.node.main.csv` рядом с манифестом. Таблица с данными (как Excel) — подходит для ведения данных, которые нужно загружать в контекст **за один раз**: счётчик изучения английских слов, списки статусов, простые каталоги.

API: `GET /api/memory/summary?path=…` — сводка для блока на overview; отдельные endpoints — `internal`, `external`, `tabular`.

### 📎 Файлы

| Режим | Файл / папка | Назначение |
|-------|----------------|------------|
| **Медиа и документы** | `_Storage/_Assets/` | Изображения, видео, аудио, PDF, sidecar `.md` к файлам |
| **Превью** | `_Storage/_Preview/` | Картинка превью ноды (`preview.jpg`, `preview.png`, …) для карточек в меню |

### 🧭 Навигация

| Режим | Статус |
|-------|--------|
| **Карта (moc)** | В разработке |
| **Индекс** | В разработке |

### ⚡ Автоматизация

| Режим | Статус |
|-------|--------|
| **Задачи по расписанию** | В разработке |
| **Heartbeat (сердцебиение)** | В разработке |

### ✨ Дополнительно

| Режим | Статус |
|-------|--------|
| **Векторизация** | В разработке |

### Редактор содержимого

| Режим | Описание |
|-------|----------|
| **Просмотр** | Rendered Markdown (markdown-it) |
| **Редактировать** | WYSIWYG (временно отключён) |

## Структура ноды

### Каноническая схема

Новые данные создаются внутри **`_Storage/`**:

```
MyNode/
  _.node.md              ← манифест и описание ноды
  _.props.yaml           ← свойства (title, tags, color, …)
  _.node.main.md      ← краткая память (опционально)
  _.node.main.csv     ← табличная память (опционально)
  _.node.todo.md         ← TODO (опционально)
  _Parts/                     ← parts (подразделы, см. ниже)
  _Storage/
    .env                      ← переменные окружения
    Configuration.md          ← конфигурации
    _Content/                 ← произвольная память (*.md)
    _Inbox/                   ← входящие
    _Referenses/              ← источники (планируется)
    _Assets/                  ← медиа и документы
    _Scripts/                 ← скрипты (*.md)
    _Preview/
      preview.jpg             ← превью для меню
  ChildNode/                  ← дочерняя нода
    _.node.md
    _.props.yaml
    _Storage/
      ...
```

### Файлы манифеста

| Файл | Роль |
|------|------|
| `_.node.md` | Обязательный. Без него папка не считается нодой. Текст режима «Описание». |
| `_.props.yaml` | Метаданные: `title`, `tags`, `color`, `priority`, `owner` и др. Отображаются в YAML-панели и влияют на UI (цвет, карточки). |
| `_.node.main.md` | **Однофайловая** память. Пара к `_.node.md` по имени. |
| `_.node.main.csv` | **Табличная** память (CSV): таблица с данными (как Excel), загружается в контекст за один раз. |
| `_.node.todo.md` | **TODO** ноды. Пара к `_.node.md` по имени. |

> **Миграция:** старые workspace с `README.node.md`, `00_MAIN.node.md`, `_Self.node.md` и связанными `*.props.yaml` / `*.node.main.md` по-прежнему открываются. Новые ноды и агенты создаются с именем `_.*`.

### `_Parts` — parts ноды

Parts — подразделы **внутри одной ноды**, не отдельные папки в дереве верхнего уровня.

Два формата:

```
MyNode/_Parts/
  Плавание.node.md            ← part как файл
  Плавание.props.yaml         ← свойства part (опционально)
  Тренировки/
    _.node.md            ← part как вложенная мини-нода
    _.props.yaml
```

Parts видны в **пространстве ноды (⚛️)** и в API; в основном дереве отображаются как элементы родительской ноды.

### Дочерние ноды

Любая вложенная папка с `_.node.md` — **самостоятельная нода** со своей `_Storage`, parts и детьми. Дерево строится по вложенности папок.

### Устаревшая (legacy) раскладка

Старые workspace могут хранить `_Content`, `_Assets`, `_Preview`, `TODO.md` или `_Storage/TODO.md` **рядом** с `_.node.md`, без канонической пары `_.node.todo.md`. CMS **поддерживает оба варианта** — при открытии ноды читается существующий файл; при сохранении создаётся `*.node.todo.md`.

Пример legacy:

```
MyNode/
  _.node.md
  _.node.main.md
  _Content/Воспоминание.md
  _Assets/photo.png
  _Preview/preview.jpg
  TODO.md
```

### Служебные папки в дереве

| Папка | В дереве | Назначение |
|-------|----------|------------|
| `_Storage/` | Скрыта | Хранилище данных ноды |
| `_Parts/` | Скрыта | Parts; содержимое доступно через API и граф |
| `.awn-framework/` | Может отображаться | Служебный фреймворк (если есть) |
| `.git` | Скрыта | Git-репозиторий; в меню — маркер Git на папке-ноде |
| `.obsidian/` | Скрыта | Конфиг vault Obsidian; в меню — маркер Obsidian на папке-ноде |

## Агенты

### Файлы Agent CMS

| Файл | Где | Назначение |
|------|-----|------------|
| **`acms.agents.json`** | корень проекта (платформа) | реестр агентов: порядок, путь, среда, `active`, default |
| **`acms.main.json`** | корень папки агента | главный манифест workspace (`id`, `name`, `comment`, …) |
| **`acms.dependencies.json`** | корень workspace | зависимости (короткий алиас: `acms.deps.json`) |
| **`acms.map.json`** | корень workspace | карта всех элементов для LLM — **зарезервировано**, пока не заполняется автоматически |

Legacy при открытии workspace: `acms.workspace.json` → `acms.main.json`; ранее `agentcms.json`, `awn.agent.json`. Реестр: `agents.registry.json` → `acms.agents.json`.

Реестр платформы: **`acms.agents.json`** — только **список** агентов (порядок, путь, среда, `active`, default). Legacy: `agents.registry.json`.

Описание workspace хранится в **`acms.main.json`** в корне папки агента:

```json
{
  "id": "my-agent",
  "name": "My Agent",
  "comment": "Заметка"
}
```

Аватар хранится отдельно: `_Storage/_Preview/preview.*` (как превью корневой ноды `_.node.md`), в манифест **не** записывается.

| Поле реестра | Описание |
|------|----------|
| **id** | Идентификатор для `?agent=` (можно переопределить в манифесте) |
| **path** | Папка с `acms.main.json` |
| **Среда** | Local / Production |
| **Def.** | Агент по умолчанию (только среди активных) |
| **● / ○** | Активность — неактивные скрыты из выбора агента |
| **Название** | Редактируется в модалке, сохраняется в `acms.main.json` (`name`) |
| **Workspace** | Только чтение — задаётся при добавлении агента |
| **Аватар** | Загрузка в модалке → `_Storage/_Preview/preview.*` |

| Поле манифеста | Описание |
|----------------|----------|
| **name** | Название в UI (редактируется в модалке) |
| **comment** / **description** | Описание агента (редактируется в модалке) |

Добавление агента: **+ Создать агента** — указать путь папки, файлы создаются внутри; или **Найти acms.main.json** — подключить существующий workspace.

Точка у **Workspace**:

- **зелёная** — `acms.main.json` найден
- **жёлтая** — папка без манифеста или не найдена
- **красная** — некорректный путь

Сохранение реестра **не создаёт и не удаляет** папки — только `acms.agents.json`. Без `acms.main.json` в workspace сохранить нельзя.

Отдельного файла «реестра всех тем для LLM» в корне workspace **нет**: контекст для модели собирается из дерева нод, API (`/api/menu`, поиск, файлы тем) и выбранной открытой ноды — не из `awn.registry.json` (устаревшее имя, убрано).

## Sidecar

**Sidecar** — markdown-заметка к медиафайлу в `_Assets`. Хранится рядом с файлом по правилу имени:

```
photo.png          ← медиафайл
photo.sidecar.md   ← sidecar (описание, теги, контекст)
```

### В интерфейсе

1. Откройте ноду → **📎 Файлы** → **Медиа и документы**.
2. У нужного файла нажмите **Редактировать**.
3. Откроется редактор sidecar; при первом открытии файл создаётся автоматически.
4. Сохраните кнопкой **Сохранить**. Кнопка **← К списку** возвращает к списку медиа.

Sidecar удобен для заметок к фото, видео и документам без переименования самого файла.

### HTTP API

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/api/media/sidecar?path=&file=` | Прочитать или создать sidecar |
| POST | `/api/media/sidecar` | Сохранить содержимое sidecar |

Подробности — в модалке **API** (`api-docs.js`).

## API и MCP — техническая справка

В шапке рядом три кнопки документации:

| | **DOC** | **API** | **MCP** |
|---|---------|---------|---------|
| Для кого | Пользователь CMS | HTTP-интеграции | Агент в Cursor / Claude Desktop |
| Источник | `user-docs-0.0.1.md` | `docs/api-0.0.1.js` | `docs/mcp-0.0.1.js` + `mcp-server/` |
| Формат | Markdown preview | Список REST-эндпоинтов | Список MCP tools → те же HTTP-вызовы |
| Версии | select в модалке | select в модалке | select в модалке |

### HTTP API

Данные отдаёт сервер: **`GET /api/docs?version=0.0.1`** (JSON, по умолчанию **0.0.1**; **0.0.0** — предыдущая). Кнопка **API** — модалка со списком эндпоинтов и выбором версии.

Большинство маршрутов работают в контексте агента: **`?agent=<id>`**. Без агента: `/api/agents`, `/api/docs`, `/api/mcp-docs`, `/api/user-docs`, `/api/public/images`.

В **0.0.1** добавлены: workspace-дашборд (`/api/agent/storage-layout`, `workspace-table`, `timeline`), reveal в ОС, `validate-paths`, версионированная справка.

Примеры групп: меню и поиск, системные файлы, нода, память (internal / external / tabular), медиа, preview, Obsidian.

### MCP Server

**MCP** (Model Context Protocol) — отдельный процесс `mcp-server/`, который Cursor подключает по stdio и вызывает **tools** (обёртки над тем же API).

1. Запустите CMS: `npm start` (http://localhost:3000).
2. Установите зависимости MCP: `cd mcp-server && npm install`.
3. В Cursor добавьте сервер (пример в модалке **MCP** или в `mcp-docs.js` → `cursorConfig`).

Переменные окружения:

| Переменная | Назначение |
|------------|------------|
| `AGENT_CMS_BASE_URL` | URL CMS (по умолчанию `http://localhost:3000`) |
| `AGENT_CMS_AGENT` | id агента для `?agent=` |

Старые имена `YAMLCMS_*` в конфиге MCP тоже поддерживаются.

Документация tools: **`GET /api/mcp-docs?version=0.0.1`**, кнопка **MCP** в шапке (select версии в модалке).

**25 tools** в mcp-server: навигация, нода, память (internal/external), todo/env/configuration, папки Inbox/…, медиа sidecar, системные файлы, `get_api_reference`.

### Навигация ноды (UI)

В разделе **Навигация** → **Карта тем**: mind map подразделов (горизонтально **→** или вертикально **↓**). Во **внешней памяти** виды: таблица, карточки, календарь, Index, Moc, **Карта**, **Шпаргалка**, граф.

## Electron и окружение

Agent CMS можно запускать в браузере (`npm start`) или как desktop-приложение на Electron.

### npm-скрипты

| Команда | Назначение |
|---------|------------|
| `npm start` | Сервер + UI в браузере (http://localhost:3000) |
| `npm run desktop` | Desktop-приложение (внутри поднимается тот же сервер) |
| `npm run pack` | Сборка без инсталлятора (`electron-builder --dir`) |
| `npm run dist` | Полная сборка (DMG/ZIP на macOS, NSIS на Windows, AppImage на Linux) |
| `npm run open:app` | Открыть собранное приложение на macOS (`dist/mac/Agent CMS.app`) |

После `npm install` скрипт **postinstall** копирует vendor-зависимости в `public/vendor/`.

### Deep links `agentcms://`

В собранном приложении зарегистрирован протокол **`agentcms`**. Формат:

```
agentcms://open?agent=main
```

Открывает Agent CMS и переключает агента через параметр URL `?agent=`. Поддерживается повторный запуск (second instance) и macOS `open-url`.

### Tray (иконка в трее)

При сворачивании окно **скрывается**, приложение остаётся в трее. Меню трея:

- **Показать Agent CMS**
- **Выход**

Клик по иконке трея — показать окно.

### Меню приложения

Стандартное меню Electron:

- **File** — Open Workspace… (`Cmd/Ctrl+O`), выбор папки проекта; закрытие / выход
- **Edit** — undo, copy, paste и т.д.
- **View** — reload, DevTools, zoom, fullscreen
- **Window** — Show Agent CMS, minimize
- **Help** — Open Logs Folder (папка логов desktop)

На macOS дополнительно меню приложения (About, Hide, Quit).

### Автообновление

В **собранном** приложении (`app.isPackaged`) подключён **electron-updater**:

- проверка обновлений через ~5 с после старта;
- загрузка в фоне;
- диалог «Доступна новая версия. Перезапустить сейчас?».

В режиме разработки (`npm run desktop` из исходников) автообновление **отключено**. URL публикации задаётся в `package.json` → `build.publish`.
