# Type.schema — справочник полей (v3)

## Поля шапки

- **Поле:** `AWN-ID`
- **Тип:** string (immutable)
- **Значение:** UUID v4 в нижнем регистре, в двойных кавычках. Пример: `"5f3a8c12-4b9d-4321-9a2b-77b1c3e88e10"`
- **Описание:** машинный уникальный идентификатор. Создаётся один раз и **не меняется** даже при переименовании или перемещении.

---

- **Поле:** `AWN-SLUG`
- **Тип:** string (mutable)
- **Значение:** `NAMESPACE/...`, верхний регистр, разделитель `/`. Примеры: `COMPONENT/SPACE`, `MEMORY/CONTENT/INNER`. Неймспейсы — справочник ниже.
- **Описание:** человекочитаемое имя типа. Slug отражает путь в дереве типов и соответствует вложенности папок в `02 Components/`. Связи между файлами идут по `AWN-ID`, а не по slug.

---

- **Поле:** `AWN-TYPE`
- **Тип:** enum (mutable)
- **Значение:** `Folder` или `File`
- **Описание:** форма ноды. `Folder` — маркер-файл внутри папки. `File` — один `.md`-файл.

---

- **Поле:** `AWN-ALLOW-CHILDREN`
- **Тип:** bool (mutable)
- **Значение:** `true` или `false`
- **Описание:** разрешены ли дочерние ноды внутри элемента. `true` — контейнер. `false` — конечный «тупик».

---

- **Поле:** `AWN-LAYER`
- **Тип:** int (mutable)
- **Значение:** целое от `0` до `5`. Расшифровка — справочник ниже.
- **Описание:** архитектурный слой контекста, к которому относится тип.

---

- **Поле:** `AWN-NAME`
- **Тип:** string (mutable)
- **Значение:** короткое имя. Примеры: `Workspace`, `Space`, `Part`, `Volume`.
- **Описание:** человекочитаемое короткое имя типа. Используется в заголовках и UI.

---

- **Поле:** `AWN-DESC`
- **Тип:** string (mutable)
- **Значение:** 1–2 строки текста.
- **Описание:** краткое описание типа — что это и зачем нужно.

---

- **Поле:** `AWN-REGISTRY`
- **Тип:** bool (mutable)
- **Значение:** `true` или `false`
- **Описание:** регистрируется ли тип в `awn.registry.md` как нода с маршрутом. `true` — попадает в реестр (`COMPONENT/SPACE`, `COMPONENT/PART`); `false` — не заносится (память, спутники, external).

## Справочники

### Архитектурные слои (`AWN-LAYER`)

| Слой | Название | Что включает                                                                  |
| ---- | -------- | ----------------------------------------------------------------------------- |
| `0`  | Vault    | Корень workspace.                                                             |
| `1`  | Folder   | Папки-ноды: Space, Cluster, Book, Collection. Общий контекст и правила.       |
| `2`  | File     | Файлы-ноды: Part. Самостоятельные объекты.                                    |
| `3`  | Memory   | Виды памяти: Content, Log, Sidecar, Volume. Следы, опыт, факты, воспоминания. |
| `4`  | Vision   | Представления данных (Views): дашборды, канбаны, mindmap.                     |
| `5`  | External | Все остальные файлы (не-ноды): медиа, скрипты, конфиги.                       |

### Неймспейсы (`AWN-SLUG`)

| Неймспейс    | Назначение                       | Примеры                                                    |
| ------------ | -------------------------------- | ---------------------------------------------------------- |
| `COMPONENT/` | Структурные ноды (Folder + File) | `COMPONENT/WORKSPACE`, `COMPONENT/SPACE`, `COMPONENT/PART` |
| `MEMORY/`    | Виды памяти                      | `MEMORY/LOG`, `MEMORY/SIDECAR`, `MEMORY/CONTENT/INNER`     |

## Генерация `AWN-ID`

macOS / Linux, без зависимостей:

```bash
uuidgen | tr 'A-Z' 'a-z'
```

Результат — UUID v4 в нижнем регистре, формат `xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx`. Записать в `AWN-ID` в двойных кавычках. После создания **не менять**.
