# Type.schema — справочник полей (v2)

## Поля шапки

| Поле                  | Тип    | Изменяемость | Значения / формат                                | Описание                                                                                                            |
| --------------------- | ------ | ------------ | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| `AWN-ID`              | string | immutable    | UUID v4 в нижнем регистре, в двойных кавычках    | Машинный уникальный идентификатор. Создаётся один раз, **не меняется** даже при переименовании или перемещении.     |
| `AWN-SLUG`            | string | mutable      | `NAMESPACE/...`, верхний регистр, разделитель `/` | Человекочитаемое имя типа. Связи между файлами идут по `AWN-ID`, а не по slug. См. неймспейсы ниже.                |
| `AWN-TYPE`            | enum   | mutable      | `Folder` \| `File`                               | Форма ноды: `Folder` — маркер-файл внутри папки; `File` — один `.md`.                                              |
| `AWN-ALLOW-CHILDREN`  | bool   | mutable      | `true` \| `false`                                | `true` — контейнер, может иметь дочерние ноды; `false` — конечный «тупик».                                          |
| `AWN-LAYER`           | int    | mutable      | `0`...`5`                                        | Архитектурный слой контекста, к которому относится тип. Расшифровка значений — таблица ниже.                        |
| `AWN-NAME`            | string | mutable      | короткое имя                                     | Человекочитаемое короткое имя типа. Используется в заголовках и UI. Примеры: `Workspace`, `Space`, `Part`, `Volume`. |
| `AWN-DESC`            | string | mutable      | 1-2 строки                                       | Краткое описание типа: что это и зачем нужно.                                                                       |
| `AWN-REGISTRY`        | bool   | mutable      | `true` \| `false`                                | Регистрируется ли тип в `awn.registry.md` как нода с маршрутом.                                                     |

## Архитектурные слои (`AWN-LAYER`)

| Слой | Название | Что включает                                                                 |
| ---- | -------- | ---------------------------------------------------------------------------- |
| `0`  | Vault    | Корень workspace.                                                            |
| `1`  | Folder   | Папки-ноды: Space, Cluster, Book, Collection. Общий контекст и правила.      |
| `2`  | File     | Файлы-ноды: Part. Самостоятельные объекты.                                   |
| `3`  | Memory   | Виды памяти: Content, Log, Sidecar, Volume. Следы, опыт, факты, воспоминания. |
| `4`  | Vision   | Представления данных (Views): дашборды, канбаны, mindmap.                    |
| `5`  | External | Все остальные файлы (не-ноды): медиа, скрипты, конфиги.                      |

## Неймспейсы `AWN-SLUG`

| Неймспейс    | Назначение                       | Примеры                                                                |
| ------------ | -------------------------------- | ---------------------------------------------------------------------- |
| `COMPONENT/` | Структурные ноды (Folder + File) | `COMPONENT/WORKSPACE`, `COMPONENT/SPACE`, `COMPONENT/PART`             |
| `MEMORY/`    | Виды памяти                      | `MEMORY/LOG`, `MEMORY/SIDECAR`, `MEMORY/CONTENT/INNER`                 |

Slug отражает путь в дереве типов — вложенность сегментов соответствует вложенности папок в `02 Components/`.

## Регистрируется в `awn.registry.md`

| `AWN-REGISTRY` | Когда                                                                  | Примеры типов                                |
| -------------- | ---------------------------------------------------------------------- | -------------------------------------------- |
| `true`         | Структурные ноды с маршрутом (триггеры, приоритет, статус)             | `COMPONENT/SPACE`, `COMPONENT/PART`          |
| `false`        | Память, спутники, external — в реестр маршрутов нод не заносятся       | `MEMORY/LOG`, `MEMORY/SIDECAR`, `MEMORY/VOLUME` |

## Генерация `AWN-ID`

macOS / Linux, без зависимостей:

```bash
uuidgen | tr 'A-Z' 'a-z'
```

Результат — UUID v4 в нижнем регистре, формат `xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx`. Записать в `AWN-ID` в двойных кавычках. После создания **не менять**.
