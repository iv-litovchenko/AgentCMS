# Команда обновления реестра нод

**Триггер пользователя:** «обнови реестр».

**Что делает:** синхронизирует `./awn.registry.md` со всеми существующими нодами `*.node.md` в vault.

## Протокол

1. Найти все `*.node.md` по всему vault (от корня). Ислкючи из поиска папки `*.package`, `*.project`.
2. Прочитать YAML-шапку каждой ноды: `AWN-STATUS`, `AWN-LOAD`, `AWN-PRIORITY`, `AWN-TRIGGERS`, `AWN-AUTOMATIZATION`, `AWN-CRON`, `AWN-NAME`, `AWN-DESC`.
3. Сверить с текущим реестром:
   - **Добавить** новые ноды, которых нет в реестре.
   - **Обновить** строки, где изменилась YAML-шапка (статус, приоритет, триггеры, расписание и т. д.).
   - **Удалить** строки нод, которых больше нет на диске.
4. Распределить ноды по таблицам реестра в соответствии с `AWN-LOAD` и `AWN-AUTOMATIZATION`:

`AWN-LOAD: start` → таблица «Реестр нод при старте».

| `AWN-STATUS` | `AWN-PRIORITY` | Путь к ноде | `AWN-NAME` | `AWN-DESC` | `AWN-TRIGGERS` |
| ------------ | -------------- | ----------- | ---------- | ---------- | -------------- |
| -            | -              | -           | -          | -          | -              |
`AWN-LOAD: on_demand` → таблица «Реестр нод по необходимости».

| `AWN-STATUS` | `AWN-PRIORITY` | Путь к ноде | `AWN-NAME` | `AWN-DESC` | `AWN-TRIGGERS` |
| ------------ | -------------- | ----------- | ---------- | ---------- | -------------- |
| -            | -              | -           | -          | -          | -              |
 `AWN-AUTOMATIZATION: true` → **дополнительно** в таблицу «Реестр нод с автоматизацией» (нода уже учтена в одной из двух таблиц выше).

| `AWN-STATUS` | `AWN-CRON` | Путь к ноде | `AWN-NAME` | `AWN-DESC` | `AWN-TRIGGERS` |
| ------------ | ---------- | ----------- | ---------- | ---------- | -------------- |
| -            | -          | -           | -          | -          | -              |

5. Реестр дополнительных файлов (читать/обновлять по необходимости)

| Файл (путь) | Описание и назначение |
| ----------- | --------------------- |
| -           | -                     |

6. Все пути в реестре — относительные от корня vault.
7. В конце файла добавь статистику в виде таблицы.

| Метрика              | Значение |
| -------------------- | -------- |
| Всего нод            | -        |
| Нод при старте       | -        |
| Нод по необходимости | -        |
| Нод с автоматизацией | -        |

---

## Правила

- Файлы без суффикса `*.node.md` в реестр **не попадают**.
- При смысловом изменении YAML-шапки ноды строка реестра обновляется при следующем запуске команды.
