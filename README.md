# AGENT CMS

**Agent CMS** — file-based CMS для совместной работы человека и LLM-агента. Без базы данных: страницы, слоты, записи, память, журнал и настройки лежат на диске в markdown и YAML. Человек работает через веб или desktop, агент — через MCP; оба видят **одни и те же файлы**.

## Три приложения

| | Назначение |
|---|------------|
| **Agent CMS** | Редактор: дерево workspace, темы и области, настройки, память, интеграции, MCP |
| **Agent CMS Voice** | Голосовой режим к тому же хранилищу — говорить с агентом, не открывая редактор |
| **Agent CMS Control** | Пульт: запуск сервера, сборки desktop-приложений, зависимости, ярлыки |

Один workspace — три входа. UI, MCP и голос — разные интерфейсы, одно хранилище.

## Зачем

Обычно агент пишет в одно место, человек смотрит в другое — расходятся версии и контекст. Agent CMS убирает этот разрыв: **общая модель Page · Slot · Content**, общие индексы, журнал и always-context. Агент может искать по смыслу, читать факты и документацию — но источник правды всегда **диск**, не чат.

## Как устроено

**Workspace (хранилище)** — корневая папка агента: темы, области, медиа, `AGENTS.md`, `settings.yml`. Это ваш проект.

**Платформа** — ядро в `agent-cms-core`: типы страниц и контента, MCP-tools, глобальные справочники и `settings.global.yml`. Одна платформа — много workspace.

**Page · Slot · Content** — базовая тройка: страница (тема или область), слот внутри неё, запись в слоте. Так устроено дерево и так агент понимает, куда писать.

**Секреты** — в `.env` (платформа и workspace). **Runtime** — в `.agent-cms/`: индексы, кэш, состояние UI, user-settings; всё пересобираемое, в git обычно не коммитится.

## Принципы

1. **Одно хранилище** — не два параллельных «мира файлов», а одно дерево для человека и агента.
2. **Файлы вместо БД** — контент и структура на диске; индексы (семантика, полнотекст, связи) строятся из файлов.
3. **Агент как пользователь** — те же страницы и tools, что у человека в UI; политика и лимиты — в настройках платформы.

## Первый старт

Этот README показывается на главной Agent CMS. Его можно вставить в чат — *«объясни Agent CMS по README.md»* — чтобы обсудить систему с нуля.

1. Установите зависимости и запустите сервер (ниже).
2. Откройте Agent CMS в браузере, выберите или создайте workspace.
3. Прочитайте `AGENTS.md` в корне хранилища — инструкции для агента именно этого проекта.
