# Личные пометки в markdown-конспектах

Система пометок для отслеживания того, что нужно повторить, доизучить или запомнить.

## Типы пометок

| Маркер | Назначение |
|--------|------------|
| `[мое повторить]:` | Нужно повторить / выучить |
| `[мое вопрос]:` | Осталось непонятным |
| `[мое заметка]:` | Личная заметка к материалу |
| `[мое важно]:` | Ключевой момент |
| `[мое ошибка]:` | Где ошибался раньше |
| `[мое идея]:` | Идея для доработки / проекта |

## Синтаксис

Маркер — отдельная строка сразу после фрагмента конспекта:

```markdown
[запись]
создано: 2026-01-05
обновлено: 2026-09-20
тема: Java / синтаксис
[/запись]

## Типы данных

`==` сравнивает ссылки, `.equals()` — содержимое.

[мое повторить]: разница между == и equals для объектов

[мое мета]
добавлено: 2026-03-10
обновлено: 2026-09-18
повторить: 2026-09-25
статус: открыто
[/мое мета]

[мое важно]: для строк всегда использовать .equals()
```

### Блоки метаданных

| Блок | Где | Поля |
|------|-----|------|
| `[запись]…[/запись]` | в начале файла | `создано`, `обновлено`, `тема` |
| `[мое мета]…[/мое мета]` | сразу после пометки | `добавлено`, `обновлено`, `повторить`, `статус` |

Статус: `открыто`, `закрыто`, `отложено`.

## Запуск

### HTML-пример (дашборд)

```bash
open examples/study-markers/03-study-markers.html
```

### CLI-скрипт

```bash
cd examples/study-markers

node collect-markers.js --input sample-notes/
node collect-markers.js -i sample-notes/ -t "мое вопрос"
node collect-markers.js -i sample-notes/ -t "мое повторить"
node collect-markers.js -i sample-notes/ -o report.html
node collect-markers.js -i sample-notes/ -o report.json -f json
node collect-markers.js -i sample-notes/ -e 03-study-markers-data.js
```

## Что собирает скрипт

Для каждой пометки: тип, текст, файл, строка, раздел (`H1 → H2 → H3`), ссылка обратно в файл, мета из `[мое мета]`.

Для файла: мета из `[запись]` (даты создания/обновления, тема).

Группировка: **тип** → **файл** → список пометок.
