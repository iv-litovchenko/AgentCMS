Трёхфазный план из первого обсуждения

  • Фаза 1. Shell v0 — компактное окно, SSE, статус, отправка в thread — ✅ сделано
  • Фаза 2. Голос — sidecar STT/TTS, режимы как в Aya (PTT, always, disabled) — ⚠️ частично
  • Фаза 3. Multi-agent — runtime registry, «кто отвечает», routing по теме/группе — ❌ не делали

Что обсуждали, но ещё не в footer

Архитектура Shell как «device runtime»

Shell должен знать, кто он и что умеет, а агент видит команды через один MCP (CMS):

  • agent-shell/manifest.yaml + GET /api/shell/capabilities
  • Shell регистрируется в CMS при старте (online + capabilities)
  • MCP tools: shell_screenshot, shell_clipboard_read/write, shell_record_screen, shell_window_minimize…
  • CMS проксирует команду → Shell выполняет → результат в thread

Сейчас только 3 shell-tools в MCP: shell_get_status, shell_post_message, shell_stop_tts.
