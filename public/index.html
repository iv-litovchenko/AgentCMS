Как искать
  • Мягкий — слова через пробел: все должны встретиться. Пробелы, дефисы и точки в именах не мешают (world war → world-of-warcraft).
  • Точный — подстрока как есть: выберите режим «Точный» или возьмите фразу в кавычки "exact phrase".
  • Маски — * любые символы, ? один символ: report*.pdf, img_???.
  • Область — «Везде» ищет в именах, метаданных тем и тексте файлов.
  • Лимит — перетащите пункт меню на иконку ◎ справа от поля, чтобы искать только внутри темы или области.
  • Тип — фильтр по формату (Markdown, PDF, видео и т.д.).
  • Смысл — локальный семантический поиск по всему workspace (offline). Индекс: sidebar → «Индексирование workspace…» → Переиндексировать.
  • ID (#) — число awn-id записи: 1847 или #1847. Откроет файл(ы) с этим id.
  • Поля — «Расширенный фильтр по полям…»: несколько условий по frontmatter (название + ключ поля из schema).

Контекстная система для LLM-агентов

Здесь вы управляете хранилищами — отдельными workspace для проектов и агентов.

  1. Создайте хранилище — папка с корневым manifest.md
  2. Откройте его — карта, список или поток на главной
  3. Наполните структурой — области, темы и записи внутри
  4. Не знаете, с чего начать? — обсудите с агентом ваши области и темы

Как подключить

Что написать агенту

  1. Шаг 1. Настройка MCP — попросите агента подключить MCP.
  2. Шаг 2. Начните новый чат и напишите агенту: 
    Выбери хранилище <Название хранилища> и загрузи контекст

    Замените <Название хранилища> на имя вашего хранилища.

  3. Шаг 3. Пообщайтесь с агентом о доступных инструментах — он всё расскажет и объяснит.
  4. Шаг 4. Не знаете, с чего начать? Спросите нейросеть — она предложит области и темы под ваши запросы и интересы.

Фокус

Быстрый навигатор

Индексирование workspace

Подготовка архива и поиск · OCR → слова → смысл → поля → связи → ID

Цепочка поверх всего workspace: текст из вложений → слова → смысл → поля → граф связей → awn-id. После сохранения .md sidecar индексы обновляются автоматически.

Реестр awn-main / awn-focus

Быстрый список «В фокусе» и «На главной» в .agent-cms/nav-registry/focus.json и .agent-cms/nav-registry/main.json. Обновляется при переключении флагов в UI; при ручном правке YAML — пересоберите реестр.

1. OCR (вложения)

Текст из jpg/png/pdf → {имя}.sidecar.md · только новые/изменённые

2. Слова (fulltext)

Точный поиск по словам · .agent-cms/fulltext-index/

3. Смысл (RAG)

Поиск по смыслу · .agent-cms/semantic-index/

4. Поля (SQL-like)

Каталог frontmatter всех .md/.yml · быстрый — только значения; полный — schema + типы/описания · .agent-cms/storage-index/

5. Связи (граф)

Wikilinks, markdown-ссылки, relation-поля · backlinks / соседи · .agent-cms/link-index/

6. ID (awn-id)

Глобальный автоинкремент для всех записей · settings.yml (Автоинкремент) · MCP: resolve_workspace_id, assign_workspace_id

7. Мониторинг

          ⚪ Банк фактов awn-facts · retain / recall

          Короткие факты и решения из любых чатов (Claude Desktop, Cursor, Voice). Пишет агент через retain_workspace_fact; поиск — recall_workspace_facts. Индексируется для semantic/fulltext.

          § Глоссарий (скоро) · term / marker

          Общий словарь терминов workspace: пометки [marker:term], [мое термин] и будущий хаб study-ecosystem. Пока только идея — без папки и без открытия.

          🟢 Синхронизация с сервером (static)

          Выгрузка и подтягивание workspace между локальной копией и сервером Agent CMS. Правило: не «агент ходит на комп», а «комп отдаёт изменения на сервер, когда онлайн». Пока комп выключен — на сервере остаётся последняя синхронизированная копия, агент продолжает работать. Google Drive у вас уже как выгрузка файлов; для 24/7 нужен полный двусторонний sync workspace ↔ сервер, не только медиа.

          ⚪ Временные файлы awn-temp · scratch / staging

          Общая папка для любых временных файлов агента и человека: черновики, staging, экспорты. Не привязана к теме — можно подпапки по задаче или дате.

          ⚪ Корзина awn-recycle · (static)

          Удалённые файлы workspace (мягкое удаление). Пока заглушка: папка awn-recycle/ для будущего восстановления и автоочистки.

          ⚪ Резервное копирование awn-backup · (static)

          Снимки и архивы workspace для восстановления. Пока заглушка: папка awn-backup/ для будущих расписаний, ручных бэкапов и отката.

          ⚪ Дашборды awn-dashboards · виджеты

          Виджеты и раскладки в awn-dashboards/: widgets/*.md + home/layout.md. Источники — внутренние (MCP, TODO) и внешние (API).

          Группы хранятся в .agent-cms-global/ws-list-groups.json. Перетащите за ⠿ группы и агентов внутри группы.

          Шпаргалка О графах и картах

          Как их обычно строят эти карты, какие параметры делают markdown-файлам в yaml-свойствах, чтобы их собрать? Интеллект-карту можно привязать к markdown-файлам и к содержимому внутри markdown-файлов — я не вижу смысл строить интеллект-карту, если за каждой из её веток не стоит markdown-файл. Верно ли я понимаю?

          Как тогда строить дорожную карту — как их обычно строят, к чему привязывают, как отмечают блоки к изучению, что изучили, что нет?

          Короткий вывод: три слоя, одна экосистема.

          Mindmap — «что вообще входит в тему» (пространство знаний).

          Roadmap — «в каком порядке идти» (лучше из диаграммы, статусы — из md/yaml). Пометки [моё *] — «что со мной лично происходит при изучении».

          Если хочешь mindmap, отталкиваешься не от цели, а от центрального понятия — карта связей между понятиями, без порядка.

          Roadmap по программированию строишь от конечной цели — порядок действий во времени, путь от точки А к точке Б.

            Тема — граница смысла: один контекст, одно намерение, одна ответственность.
            Не смешивай задачи в одном файле — разводи их по дереву.
            Память накапливается заметка за заметкой, а система остаётся прозрачной.
            «Файл — это не папка, а намерение.»
          
          
          
          
            Мышление алгоритмами и структурами данных:
            класс = форма, новый тип в системе (пример: цифра),
            объект = экземпляр в «реальном мире» (пример: единица «1»).
          
          
          
          
            Проблема большого контекста: загрузил книгу на 1000 страниц — неизвестно, что LLM посчитает важным, а что нет.
            Без правильных вопросов и без человека не обойтись.
          
          
          
          
            Система расширяется изнутри: онтология и контент наращиваются топиками, типами и справочниками
            прямо в workspace — без перестройки ядра.
            Исполнение — loaders, API, UI, MCP — пока живёт в коде;
            core workspace описывает правила и задаёт эталон.
            CMS — язык мира агента, JavaScript — его интерпретатор.
            (То есть: онтология и контент — саморасширяемы, поведение runtime — пока задаётся кодом, а core workspace только документирует и этalon-ит правила.)

            Model Context Protocol (MCP) — способ подключить внешний сервер к IDE (Cursor, Claude Desktop). Ниже — виды
            возможностей по спецификации. В Agent CMS сейчас реализованы в основном Tools; остальное —
            для понимания протокола.
          
                
          
                
            
                Виды возможностей MCP
                
            
                
              
                
                TOOL
                tools / tools/call
              
                
              
                
                Действия: вызов функции с аргументами и ответом (JSON или текст). Агент сам решает, когда вызвать.
                Список ниже в этой модалке — это tools Agent CMS (list_workspaces,
                database_frame_get, …).
              
                
            
                
            
                
              
                
                RESOURCE
                resources / read
              
                
              
                
                Чтение данных по URI без «команды»: документ, индекс, снимок контекста. Клиент подтягивает resource в чат,
                когда нужно. У Agent CMS пока не exposed; аналог — HTTP /api/mcp-docs или tools вроде
                get_session_context.
              
                
            
                
            
                
              
                
                PROMPT
                prompts / get
              
                
              
                
                Готовые шаблоны сообщений с параметрами — обычно пункты меню в IDE («разбери inbox», «настрой workspace»).
                Не заменяют tools; ускоряют старт сценария для человека.
              
                
            
                
            
                
              
                
                CAPABILITY
                initialize
              
                
              
                
                Не отдельная кнопка для пользователя: сервер при подключении сообщает, что умеет (tools, resources, prompts,
                версии). Клиент строит список доступного.
              
                
            
                
            
                
              
                
                ROOT
                roots
              
                
              
                
                Границы файловой системы: какие папки MCP-серверу разрешены. Нужно для file-based серверов; у Agent CMS доступ
                идёт через API workspace и agentId, не через прямой диск IDE.
              
                
            
                
            
                
              
                
                SAMPLING
                sampling
              
                
              
                
                Сервер просит клиент сделать мини-запрос к модели (ответ LLM через IDE). Редко нужно, если вся логика в чате
                пользователя.
              
                
            
                
          
                
          
                
            Подсказки в жёлтой полосе выше и JSON для Cursor — для людей при настройке. Модель в чате по умолчанию видит
            описания tools из MCP, а не эту модалку.
